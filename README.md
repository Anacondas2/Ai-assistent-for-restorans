# ИИ-агент для ресторанов Гамбурга

Настраиваемый ИИ-агент, который от лица ресторана общается с гостями,
бронирует столики и отвечает на вопросы о меню. Его можно настроить под
любой ресторан (через файл конфигурации) и продавать по подписке.

Полное описание проекта, решения и план — в файле [`ПЛАН.md`](./ПЛАН.md).

## Что уже готово (этап 1: ядро бронирования)

Самая ответственная часть — логика «свободно/занято». Она:

- знает столы ресторана и их вместимость;
- учитывает длительность визита (2–4 чел. → 2 часа, больше → 3 часа; настраивается);
- **не допускает двойных броней** (стол занят, если время пересекается);
- создаёт, **переносит и отменяет** брони;
- помечает, что компании **от 7 гостей нужен депозит 50 €**;
- отклоняет брони вне часов работы и дальше горизонта (90 дней);
- передаёт «человеку» случаи, которые сама решать не должна (очень большие компании);
- умеет записывать важную информацию от гостя (аллергии, повод, пожелания).

Всё это покрыто автотестами (11 шт.), которые проверяют главное — что агент
не посадит два стола на одно время.

## Что готово (этап 2: «мозг» агента)

Поверх ядра добавлен слой Claude: гость пишет обычным языком, агент понимает
и сам вызывает нужные операции (проверить место, забронировать, перенести,
отменить, передать человеку, записать заметку). Главное:

- **6 инструментов** агента, привязанных к протестированному ядру;
- системный промпт на немецком с характером «дружелюбный, с лёгким юмором»;
- **жёсткая защита по аллергенам**: агент называет аллергены только из
  меню; в спорных или опасных случаях не утверждает безопасность, а передаёт
  вопрос персоналу (важно по закону Германии LMIV);
- уведомление о записи разговора (GDPR);
- кэширование меню/правил для удешевления каждого ответа.

Диспетчер инструментов покрыт тестами (без обращения к API). Всего **21 тест**.

## Структура проекта

```
restaurant_ai/
  config.py          — настройки ресторана (столы, часы, правила)
  db.py              — хранилище броней (SQLite)
  availability.py    — логика «свободно/занято» (защита от двойных броней)
  booking.py         — создать / перенести / отменить бронь
  tools.py           — инструменты агента + связка с ядром
  agent.py           — системный промпт + разговорный цикл с Claude
  configs/
    napoli.json      — пример настройки ресторана («60 seconds to napoli»)
    napoli_menu.md   — пример меню с аллергенами (требует подтверждения)
demo_chat.py         — запуск демо-чата (нужен ключ ANTHROPIC_API_KEY)
tests/
  test_availability.py — автотесты ядра
  test_dispatch.py     — автотесты инструментов агента
```

## Как попробовать живой чат

```bash
pip install -r requirements.txt
export ANTHROPIC_API_KEY=...    # ваш ключ Claude
python3 demo_chat.py
```

## Как настроить под новый ресторан

Скопировать `restaurant_ai/configs/napoli.json`, поменять название, адрес,
часы работы, список столов и правила. Код менять не нужно — это и есть
«настройка под каждый ресторан».

## Как запустить тесты

```bash
python3 -m unittest tests.test_availability -v
```

## Что дальше (по плану)

1. **«Мозг» агента** — слой Claude: гость пишет обычным языком, агент
   понимает и вызывает нужные операции (проверить место, забронировать,
   перенести, отменить, передать человеку).
2. **Знание меню/аллергенов** — с жёсткой защитой от выдумывания (важно
   по закону Германии о раскрытии аллергенов).
3. **Канал** — веб-чат на сайте и/или Telegram.
4. **Панель управления** для ресторана и мультиарендность (для продаж).

> Технические заметки соответствия GDPR (запись разговоров, согласие,
> хранение данных в ЕС) ведутся отдельно — это обязательно для Германии.
